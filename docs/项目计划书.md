# 沿海气象灾害实况预警网站项目计划书

**版本：** 1.0  
**日期：** 2026-11-16  
**项目阶段：** 立项与产品规划  
**项目代号：** 海岸安

---

## 一、项目概述

### 1.1 项目背景

沿海地区居民、渔民、养殖户和基层单位面对台风、短时强降雨及其引发的风暴潮、内涝、山洪、滑坡等风险时，需要快速回答三个问题：**我所在的地方有没有风险、风险何时到达或增强、现在应该采取什么行动。**

现有预警信息常分散在天气应用、政府网站、社交平台和工作群中，专业术语较多，地图位置与基层行政区划不易对应。部分用户网络条件有限，渔船船员和偏远村镇居民也需要更醒目、更易理解的信息呈现。

### 1.2 项目定位

建设一个服务沿海场景的气象灾害信息聚合与传播网站，以“区县本地风险优先”为入口，将官方预警、台风路径、降雨云团实况、地图标绘和通俗避险行动提示放在同一页面。

本项目是**信息服务和传播平台**。它不替代气象主管机构及其所属气象台站发布预警，不自行制造或变更官方预警等级，不替代政府应急指挥和救援渠道。

### 1.3 项目目标

1. 让用户进入网站后尽快看到当前位置或所选区县的有效台风、暴雨风险。
2. 用地图和简明文字呈现风险位置、移动趋势、影响时段及数据更新时间。
3. 按用户场景提供可执行的避险提示，降低理解专业天气信息的门槛。
4. 为村镇、学校、渔业生产单位和基层应急人员提供可转发、可查看来源的风险页面。
5. 建立可追溯的数据接入、失效降级和信息纠错机制，为后续扩展积累基础。

### 1.4 目标用户

| 用户群体 | 主要关注 | 设计重点 |
|---|---|---|
| 沿海村镇居民 | 本地是否预警、是否需要转移、停电停水准备 | 区县优先、简明行动清单、大字号 |
| 渔船船员、渔民 | 海上风力、台风路径、返港避风时间 | 移动方向、海域图层、低带宽可读 |
| 近海养殖户 | 风浪降雨影响、加固与人员撤离 | 养殖区域附近风险、分步骤提示 |
| 沿海商铺与企业 | 防风加固、排水、停业准备 | 预警生效与更新状态、快速转发 |
| 学校、基层应急人员 | 预警范围、通知对象、行动建议 | 区域筛选、来源可核查、信息时效明确 |

## 二、产品范围与核心功能

### 2.1 首页：本地风险总览

- 首次访问时说明定位用途并请求浏览器定位授权；仅在授权后读取位置。
- 通过坐标匹配区县，优先显示该区县及邻近沿海区域的有效官方预警。
- 定位失败、用户拒绝或设备不支持时，允许按省、市、区县手动选择；记住选择需征得用户同意。
- 首页卡片呈现灾种、官方级别、影响区域、发布时间、预计有效期、来源气象台站和数据新鲜度。
- 同时存在多种风险时，按官方级别和有效性排序，并提供风险列表；排序规则可由运营配置并公开说明。
- 页面顶部提供“信息来自哪里”和“最后更新时间”，过期或上游故障时显示醒目的状态提示。

### 2.2 台风模块

呈现字段：

- 台风名称、编号、当前强度或等级（以数据源字段为准）。
- 台风中心当前位置和观测/分析时间。
- 移动方向、移动速度、中心附近最大风力/风速（标明单位与含义）。
- 官方台风预警信号：蓝、黄、橙、红四级；标明发布机构、发布时间、影响区域、有效时间及防御指南。
- 地图展示当前位置、已观测路径、官方预报路径及其时间点；不同数据属性使用不同图例，不混画为确定路径。
- 面向居民、渔船、养殖户和基层单位提供分场景避险提示。
- 当没有活跃台风时显示无活跃台风数据及最近更新时间，不用旧数据造成“仍在影响”的误解。

### 2.3 暴雨云团模块

呈现字段：

- 云团名称或编号；若上游无正式命名，则使用平台内部编号并明确标注。
- 云团当前位置、观测时刻、移动方向和速度（仅在数据源支持且可信时展示）。
- 雨强/降水强度、累计降雨等实况字段，注明指标定义、单位、时间窗口与数据来源。
- 雷达回波或降雨实况图层，并在图例中说明颜色含义和更新时间。
- 官方暴雨预警信号：蓝、黄、橙、红四级，以及发布机构、发布时间、影响范围、有效时间和原始防御指南。
- 提供短时强降雨、积水、山洪、地质灾害和临水风险的分场景提示；涉及其他部门监测的风险须标注对应主管部门来源。

**边界说明：**“云团”是实况监测或分析对象，云团编号、雨强和移动趋势不能自动等同于官方暴雨预警。平台不得根据自建阈值生成官方预警颜色；可以在完成气象业务审核后，另行呈现清晰标识的“平台风险提示”，并与官方预警严格区分。

### 2.4 地图与区县标绘

- 地图支持台风路径、云团/雷达图层、官方预警影响区、用户所在区县和重点区域标注。
- 地图图层可开关，图例与数据时间始终可见；移动端优先展示本地范围，支持缩放与定位。
- 预警影响区域必须来自权威数据或经授权的结构化信息；无法获得精确边界时展示官方文字范围，不自行绘制精确多边形。
- 区县定位需处理行政区划代码映射与边界变化；定位结果用于展示附近风险，不代表对用户实际安全状态的保证。
- 提供地图文字列表作为替代，照顾屏幕阅读器、弱网和地图服务不可用场景。

### 2.5 通俗避险提示

提示按“现在做什么 / 接下来准备什么 / 避免做什么”组织，优先使用短句和动作词。至少覆盖：

- 居民：远离海边、河道、地下空间和易涝点；关注转移通知；检查门窗、电源和应急物资。
- 渔船与海上作业：关注海事、渔业主管部门和气象台信息；按主管部门要求返港、避风或停止作业。平台不发布航行许可或海上调度命令。
- 养殖户：提前加固设施、转移人员和重要设备；按当地预案执行，不为抢收冒险下水。
- 学校、商铺和基层单位：依照属地预案落实停课停业、人员清点、广播通知等措施。
- 所有提示显示适用灾种、级别/情景、来源、版本和复核日期；当地气象部门或应急部门审核后发布。

### 2.6 传播与无障碍（后续阶段）

- 一键生成带来源、时间、区域和链接的风险分享卡片，适配微信群、短信和村镇工作群转发。
- 高等级预警可配置站内提示或订阅通知；任何推送都应保留原始发布来源、时间和解除/更新状态。
- 设计高对比度、色彩加文字/图标双编码、大字号和键盘可操作界面。
- 预留简体中文、语音播报及方言/少数民族语言内容扩展能力；首期先完成标准中文与适老化阅读。
- 对弱网提供轻量列表、缓存最近一次数据并显著注明缓存时间；不将缓存内容展示为实时状态。

## 三、预警分级与信息治理

### 3.1 四级展示规则

全国气象灾害预警信号常按蓝色、黄色、橙色、红色对应Ⅳ、Ⅲ、Ⅱ、Ⅰ级展示。台风与暴雨页面应分别呈现官方发布的四级信号。具体触发标准、防御指南及地方补充规定须以项目覆盖地区现行有效的规定和当地气象台站发布内容为准。

| 展示级别 | 常见颜色 | 页面行为建议 |
|---|---|---|
| Ⅳ级 / 一般 | 蓝色 | 显示预警卡片和基础准备提示 |
| Ⅲ级 / 较重 | 黄色 | 提高本地卡片优先级，突出准备行动 |
| Ⅱ级 / 严重 | 橙色 | 首页显著提示，强化影响区域与即时行动 |
| Ⅰ级 / 特别严重 | 红色 | 最高优先级展示；提示立即遵从属地政府和主管部门指令 |

表中名称属于常见框架；地区适用等级名称、信号标准、发布流程可能存在差异，实施前须按属地规则核实。

### 3.2 数据展示原则

每条预警或实况至少记录并显示：

- 来源机构与数据产品名称。
- 数据观测/预报时间、发布时间、接收时间和页面更新时间。
- 预警开始与结束时间、影响区域、级别和状态（生效、变更、解除、过期）。
- 数据字段单位、坐标系或空间参考说明（适用时）。
- 上游数据延迟、缺失、重复或纠错状态。

### 3.3 数据获取与合作

优先顺序：

1. 与中国气象局、省市县气象部门或其授权服务渠道建立合规数据合作。
2. 对接有明确授权与服务等级的气象数据服务商。
3. 使用公开发布内容时，确认许可、抓取/转载规则、接口稳定性及展示要求。

项目立项后应确认数据授权范围、商业使用许可、调用限额、更新频率、历史数据留存、突发流量保障及应急联系人。不得依赖未经授权的网页抓取作为生产预警主链路。

## 四、信息架构与关键用户流程

### 4.1 网站信息架构

- 首页：本地风险总览 / 选择地区 / 数据时间与来源。
- 台风：台风列表 / 单个台风详情 / 路径地图 / 风险提示。
- 暴雨云团：云团列表 / 实况详情 / 雷达与降雨图 / 官方暴雨预警。
- 避险指南：按灾种、用户角色和预警等级查找。
- 数据与服务说明：来源、更新时间、定位说明、故障状态和反馈入口。

### 4.2 关键流程

**首次访问：**首页说明定位用途 → 用户授权或手动选择区县 → 展示本地生效预警 → 用户查看地图、来源和行动提示。

**预警更新：**接收权威数据 → 校验签名/来源及时间字段 → 去重和状态转换 → 按区县映射 → 更新页面与缓存 → 记录审计日志。

**上游中断：**健康检查识别延迟 → 页面保留最后成功数据并标为“更新时间/数据可能延迟” → 到达失效阈值后停止显示为有效实时数据 → 展示官方渠道入口。

## 五、技术方案建议

### 5.1 总体架构

- **前端网站：**响应式 Web，支持桌面、手机和平板；可评估渐进式 Web 应用能力。
- **后端 API：**负责统一数据模型、区县查询、预警聚合、来源与时间校验、访问控制和审计。
- **数据接入层：**适配气象部门或授权服务商接口；分开接入预警、台风路径、雷达/降水实况等数据。
- **地图服务：**接入具备相应授权的底图、行政区划边界与气象图层；根据实际许可选择渲染方式。
- **存储与缓存：**关系型数据库保存结构化预警与审计元数据；缓存用于热点区县查询，明确缓存过期策略。
- **监控告警：**监控接口延迟、数据时效、错误率、地图/瓦片可用性和通知送达状态。

### 5.2 数据模型草案

- Alert：灾种、级别、颜色、标题、正文、发布机构、发布时间、开始/结束时间、影响区域、状态、来源链接。
- Typhoon：国际/国内编号、名称、中心经纬度、分析时间、移动方向/速度、风力/风速、路径点集合、预报点集合。
- RainCell：内部或上游编号、中心位置、观测时间、移动方向/速度、雨强指标、空间范围、来源。
- Region：行政区划代码、名称、上级代码、边界版本、沿海/重点区域属性。
- DataStatus：来源、最后成功时间、延迟秒数、健康状态、错误摘要。

数据结构需能保存原始来源字段与规范化字段，便于核验和回溯。

### 5.3 可靠性与安全

- 上游接口设置超时、重试、熔断、配额和告警；预警信息变更需幂等处理。
- 重要数据操作保留审计日志；后台管理采用最小权限、多因素认证和操作留痕。
- 定位默认仅在用户授权后使用；按最小必要原则处理坐标，优先在前端完成区县匹配，服务端不长期保存精确定位。
- 全站 HTTPS；防止脚本注入、越权访问、数据投毒和恶意刷接口。
- 生产环境设置备份、恢复演练和应急发布流程；建立内容纠错和紧急下线机制。
- 页面提供“此信息仅作气象信息参考，请以当地气象台和政府部门最新发布为准”的清晰说明，但不能以免责声明取代准确、及时展示义务。

## 六、运营与治理机制

- **数据负责人：**维护接口合同、字段映射、时效阈值和故障升级机制。
- **气象内容审核：**由具备相应专业能力的人员/合作单位审核避险文案和展示规则。
- **属地联络：**与目标省市的气象、应急、海事、农业农村、教育等部门确认传播与使用边界。
- **内容维护：**预警指南按地区、灾种和版本管理，记录审核人、发布日期与复核日期。
- **用户反馈：**提供错误信息反馈入口和处理时限；涉及生命安全的情况引导用户联系当地应急/救援渠道。
- **演练机制：**在汛期前进行模拟数据、接口中断、预警升级/解除和高并发演练。

## 七、实施阶段与里程碑

以一个沿海试点省份或地市为范围，建议按约 12 周规划；正式排期取决于数据授权、地图许可和属地合作进度。

| 阶段 | 周期 | 主要工作 | 阶段交付 |
|---|---:|---|---|
| 0. 立项与核验 | 第1–2周 | 明确试点区域、责任主体、数据授权、预警规则、地图许可与验收指标 | 需求基线、数据清单、合规与合作确认 |
| 1. 产品与交互设计 | 第3–4周 | 首页、区县定位、台风/暴雨详情、地图图例、避险内容设计 | 原型、字段字典、内容审核清单 |
| 2. 核心开发 | 第5–8周 | 数据接入、API、地图图层、响应式界面、区县风险排序 | 可演示 MVP、后台数据健康状态 |
| 3. 联调与试点 | 第9–10周 | 历史过程回放、属地审核、弱网与故障降级、用户试用 | 试点反馈、问题清单、修订版本 |
| 4. 上线准备 | 第11–12周 | 监控、应急值守、文档培训、演练及上线评审 | 上线检查单、运维手册、发布批准 |

**建议 MVP 范围：**单一沿海试点区域、区县手动选择与可选定位、官方台风/暴雨预警列表、台风路径、暴雨实况图层（以数据授权为准）、本地行动提示、来源与更新时间、故障降级。订阅推送、全省推广、用户账号和复杂运营后台进入后续迭代。

## 八、资源与成本构成

当前缺少试点地区、数据授权报价、团队规模和服务量数据，不宜给出未经依据的总预算。立项阶段按以下项目询价并形成预算：

- 产品设计、前后端、数据工程、测试与项目管理人力。
- 气象数据授权与技术支持费用。
- 地图底图、空间数据及地图 API 调用费用。
- 云资源、存储、CDN、监控、备份和短信/消息服务费用。
- 气象内容审核、属地协调、培训与汛期值守费用。
- 安全评估、隐私合规、等保或其他适用要求的咨询与整改费用。

预算评审需区分一次性建设费用、年度数据/地图授权费、峰值流量成本和汛期运维值守成本。

## 九、验收指标建议

首期试点通过以下指标验收，具体阈值在数据合作确定后固化：

- **数据可追溯：**页面展示的数据来源、发布时间、有效期和更新时间完整率达到 100%。
- **预警状态准确：**发布、更新、解除、过期状态与授权源一致；建立抽样核验机制。
- **本地化可用：**用户可通过授权定位或手动选择抵达区县风险页；定位失败有可用回退。
- **时效可见：**每个数据模块均有明确时效阈值，超时自动提示延迟或停止实时呈现。
- **地图可理解：**台风实况/预报路径、雨强图层和官方预警区域图例通过目标用户可用性评审。
- **行动提示可读：**目标用户测试中能在短时间内正确回答“当前风险、何时生效、应做什么”。
- **可用性与性能：**核心页面在约定网络、设备和并发条件下满足项目约定的加载和稳定性目标。
- **故障降级：**模拟上游中断时，页面能识别数据陈旧、保留来源和时间，并给出官方渠道入口。

## 十、主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据授权未落实或接口变更 | 无法稳定提供实时产品 | MVP 前完成书面授权和接口 SLA；保留备选授权供应方 |
| 数据延迟、缺失或错误 | 用户依据过期信息行动 | 显示数据时间、监测心跳、陈旧阈值、来源直达和降级模式 |
| 平台提示被误认为官方预警 | 引发错误决策或责任争议 | 官方信号与平台分析分区展示；不改级别、不伪造发布机构 |
| 云团识别与影响范围不确定 | 造成过度或不足警示 | 标明“监测/分析”属性、置信度和数据来源；不等同官方信号 |
| 地方预警规则存在差异 | 颜色/指南不适用 | 按属地配置，启动前由当地气象主管部门或合作方确认 |
| 定位精度或区县边界错误 | 本地风险筛选不准确 | 明示定位区域，可手动改选；提供附近区县与地图查询 |
| 弱网、断网或海上无信号 | 用户看不到更新 | 页面轻量化、缓存带时效标签、提供短信/广播等互补传播渠道 |
| 预警期访问激增 | 页面不可用 | CDN、缓存、容量压测、静态降级页和上游限流保护 |
| 避险文案不符合属地处置要求 | 错误行动建议 | 内容审核、版本管理、属地应急预案对齐和定期复核 |

## 十一、待立项确认事项

1. 首期试点省、市、县及面向用户的服务责任主体。
2. 台风路径、暴雨云团/雷达、官方预警的正式授权数据源和 SLA。
3. “云团名称/编号”采用哪一数据源的命名；缺少官方名称时采用何种内部标记。
4. 地图底图、行政区划边界、海域数据和坐标转换许可。
5. 是否需要短信、微信服务号、企业微信或应急广播联动；各渠道的授权和责任主体。
6. 定位数据处理、隐私政策、数据保存期限及安全评估要求。
7. 避险提示审核部门、内容责任人和值守机制。
8. 上线验收阈值、汛期运维预算、故障联系人和应急处置流程。
